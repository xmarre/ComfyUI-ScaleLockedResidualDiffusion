# ComfyUI Scale-Locked Residual Diffusion v1.2.0

## Scope

This feature release consolidates the Krea 2 sampling controls introduced in
PR #15, the extended handoff, native solver, SesquiLSR and spectral progressive
implementation from PR #16, and the uncapped planner control from PR #17.
The generic (non-Krea) Scale-Locked sampler nodes retain their existing
defaults and behavior.

## Added

- **Five Krea 2 regeneration modes:**
  - `trajectory`: planner-following composition lock and target refinement,
    with optional completed-latent handoffs between intermediate stages.
  - `planner_final_img2img`: complete each lower-resolution latent, upscale
    it and run a native diffusion suffix at `img2img_start_sigma`.
  - `planner_final_upscale_only`: enlarge a completed planner through a latent
    upscaler with zero target denoiser evaluations.
  - `planner_final_native_refine`: refine once within the 2048-pixel native
    range, then enlarge with SesquiLSR without a >2048-pixel DiT pass.
  - `spectral_progressive`: a single trajectory with noisy-state spectral
    expansion, aligned sigmas and manually scheduled or calibrated
    resolution transitions.
- **Native Krea 2 sampler controls** for CFG, schedule, Euler, DPM++ 2M,
  RES Multistep, DEIS, iPNDM/iPNDM-V, Gradient Estimation, ER-SDE and
  SA-Solver/SA-PECE. Integration preserves the solvers' numerical update
  contracts and provides per-stage seeded, patch-coupled stochastic noise.
- **Spectrum Krea 2 forecasting support** on qualified native sampler paths,
  including separate planner predictor-forecast control, predictor/corrector
  accounting and fail-closed compatibility checks.
- **SesquiLSR Wan 2.1 learned latent upscaler**, with bundled weights and MIT
  attribution, for completed-latent handoffs; intermediate resolution stages
  can use it without introducing extra diffusion stages.
- **Spectral calibration and handoff diagnostics**, including a five-panel
  latent viewer for recorded sampling stages.
- **Planner UI cap raised** from 4 MP to the canvas-derived
  `MAX_MEGAPIXELS` (256 MP at the current 16384-pixel canvas limit).
  This removes the widget cap; it does not imply that enormous planner
  canvases are usable or desirable.

## Updated Krea 2 defaults and compatibility

- Node default `steps`: **8 → 12**.
- Node default `composition_lock_sigma`: **0.80 → 0.65**.
- Keep `planner_megapixels=1.0` by default because a 3.5 MP planner is
  invalid for outputs at or below 3.5 MP. Output size is supplied by the
  LATENT input, not fixed by this node.
- Keep `regeneration_mode=trajectory`, `cfg=1.0`,
  `sampler_name=euler`, `scheduler=simple`,
  `max_stage_upscale=4.0` **area ratio**,
  `coarse_lock_strength=mid_lock_strength=0`, and
  `latent_upscale_method=interpolate` as generic compatibility defaults.
  Explicitly enable SA-PECE and SesquiLSR for the tested high-resolution
  profile below.
- Stored manual `progressive_transition_sigmas` values are ignored outside
  spectral progressive; their validation and effect resume when selected.
  Spectral progressive similarly ignores a stored `sesqui_wan21` selection,
  because it has no completed-latent handoff. No manual clearing is needed
  when switching between these modes.
- Existing saved widget positions remain stable. Stored widget values
  continue to override new defaults.
- Manual spectral transition sigmas and an active spectral-calibration source
  are mutually exclusive **in spectral progressive**; disconnect the
  calibration when selecting a manual schedule.

## Reported 4096 × 4096 high-resolution profile (16.78 MP)

User-reported November 11, 2026 trials on an RTX PRO 6000 Blackwell
96 GB GPU with a custom merged Krea 2 checkpoint found the following
`trajectory` setup visually preferable:

| Setting | Value |
|---|---|
| Final LATENT canvas | 4096 × 4096 (16.78 million pixels) |
| Planner | `planner_megapixels=3.50` (1872 × 1872) |
| Intermediate | `stage_megapixels=8` or automatic (`max_stage_upscale=4`) |
| Automatic intermediate output | approximately 2768 × 2768 (7.66 MP) |
| Scheduler, sampler, steps | `simple`, `sa_solver_pece`, **12** |
| Spectrum | Krea 2 `turbo`, warmup 2, degree 1, window 1, tail 1 |
| CFG, composition release | **1.0**, `composition_lock_sigma=0.65` |
| Post-release band locks | coarse **0**, mid **0** |
| Completed-stage upscaling | `latent_upscale_method=sesqui_wan21` |

This canvas is **beyond Krea 2 Turbo's documented 2048-pixel-axis
inference range**. Successful runs do not establish a general resolution
ceiling, anatomical accuracy across prompts, or GPU memory safety on other
hardware. The planner MP and intermediate stage depend on **final output
MP** and should not be used blindly at smaller resolutions.

### Alternative regeneration modes evaluated

- **`planner_final_img2img`** with `img2img_start_sigma=0.70`:
  12-step setup, 5 suffix steps at each of the 7.66 and 16.78 MP stages;
  reported wall time **117.72 s**. It permits more independent refinement
  and may alter anatomy; trajectory was visually preferred.
- **`spectral_progressive`** with manual
  `progressive_transition_sigmas=0.80, 0.65`: a **6/2/4** split of
  12 diffusion steps across 3.50/7.66/16.78 MP, reported **86.91 s**.
  Automatically calibrated runs allocated **9/1/2** or **8/1/3**; one
  reportedly duplicated a belly button. Manual transitions were preferred
  over those schedules but are not proven universally reliable. This mode
  does not run SesquiLSR.

These timings are individual end-to-end application runs, including
downstream postprocessing, not controlled benchmarks. The user supplied
sampler logs and visual assessments, not a reproducible multi-seed image
benchmark. Image-quality conclusions remain provisional.

## Validation and limitations

GitHub Actions validates CPU numerical invariants, widget contracts and
native ComfyUI Krea 2 integration against a pinned tiny random-weight
model, including mode switching, stochastic noise alignment, spectrum
transition invariants and interruption cleanup. These checks do not prove
real-checkpoint image quality, identity consistency, anatomy or GPU
throughput. See README for detailed algorithms, numerical restrictions,
setup and the complete high-resolution profile.

**Upgrade:** Use the released v1.2.0 package via your normal installation
manager/Patcher. PR overlays #15/#16/#17 were development inputs to
this release and should not be stacked again on top of an installed
v1.2.0 main-branch release.

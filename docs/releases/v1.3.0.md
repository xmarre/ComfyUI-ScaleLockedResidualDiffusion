# ComfyUI Scale-Locked Residual Diffusion v1.3.0

## Scope

This feature release adds automatic Krea 2 completed-latent refinement and
resolution-stage budgeting to the native sampler controls in v1.2.0.
The generic Scale-Locked samplers and the Krea 2 `trajectory` default retain
their established behavior. The new modes and stage policy are opt-in.

## Added

- **`trajectory_auto` regeneration:** keep the existing planner and initial
  high-resolution trajectory behavior. For later completed-latent stages,
  estimate detail and structure scales from the enlarged source latent and
  automatically select a shorter native-sigma restart suffix when appropriate.
  The method may retain the legacy restart when the evidence is insufficient.
- **`trajectory_auto_native`:** use a first refinement within Krea 2 Turbo's
  documented 2048-pixel-per-axis inference range where a larger native-range
  grid exists between the planner and target. Subsequent stages restart from
  completed latents with automatic selection. With no feasible in-range
  intermediate (for example, a planner already taller than 2048 pixels), use
  the existing out-of-range trajectory restart without fabricating a native stage.
- **`stage_planning=auto_two_passes`:** derive the maximum per-stage pixel-area
  growth directly from the connected final LATENT and the rounded planner
  grid. When a native intermediate exists, choose planner → native-range
  refinement → target, with a 2% growth-cap margin. When no native
  intermediate exists, use one direct high-resolution pass. Despite its
  name, this policy does not guarantee two passes in that case.
- **Restart diagnostics:** log the stage dimensions, sigma and steps selected,
  the legacy alternative, and the policy decision. Supported schedules can
  retime a short two-step suffix when the existing native restart would
  otherwise start above an estimated structure limit.
- **Planner-reference diagnostics:** in
  `handoff_diagnostics=log_and_save_latents`, perform an additional
  independent stock-ComfyUI planner pass, report a numerical comparison,
  and save `planner_stock_ksampler.latent` for the supported stock-compatible
  sampler/options combinations. Configured ER-SDE and SA-Solver variants
  are skipped because stock KSampler cannot receive their custom options
  or match their stochastic innovations automatically.

## Compatibility and setup

- The new `stage_planning` widget is appended after the existing Krea 2
  controls. Its default is `manual`; existing saved widget positions,
  existing stage schedules, the `trajectory` default, and all other
  regeneration modes retain their behavior.
- Automatic stage planning is active **only** with
  `regeneration_mode=trajectory_auto_native` and an empty
  `stage_megapixels` field. Explicit stage lists take precedence; manual
  mode retains `max_stage_upscale` as the per-stage *area-ratio* limit.
- Existing `ScaleLockedResolutionSelector` and `EmptyLatentImage` nodes
  supply the target resolution. No second resolution selector and no new
  workflow connections are required.
- The automatic policy is a stage-count policy, **not a semantic quality
  detector**. Reducing the number of denoising stages may preserve details
  in some scenes, but large jumps can also lose detail or change anatomy.
- The planner uses the connected MODEL, including any LoRAs and external
  model patches. Diffusion accelerators and conditioning patches can
  independently change image details, likeness or geometry. The stock
  planner comparison does not remove those patches.

## Validation

- GitHub Actions exercises numerical invariants, node-input compatibility,
  restart policy, per-stage state isolation, and native ComfyUI Krea 2
  integration with CPU models.
- A user-provided real-checkpoint ER-SDE run with a 1632×2448 planner and
  3744×5616 target completed using `auto_two_passes`. Because the planner
  already exceeds the native-range axis, the reported
  `native=unavailable` and **one** high-resolution pass are the
  documented fallback. This single run verifies execution of that path,
  not universal visual fidelity.
- Independently saved planner and stock-KSampler latents were bit-identical
  for a stock-compatible diagnostic run with the same MODEL and conditioning.
  This supports planner-path parity for that configuration, not exact
  equality across all solver choices.

## Limitations

- Krea 2 Turbo inference above 2048 pixels on either axis is experimental.
  The native-range first stage is unavailable when the planner already
  exceeds the supported range.
- Detail/structure proxies do not detect whether newly generated semantic
  structures are correct. The minimum two-step suffix can retain or amplify
  incorrect features, and extra model patches can cause differences much
  earlier in the planner.
- Passing CPU tests and individual GPU executions does not establish
  multi-prompt image quality, identity consistency or anatomical accuracy.

## Upgrade

Install v1.3.0 through the usual ComfyUI manager or ComfyUI Patcher
release workflow. If a development overlay for PR #18 is active, remove
that **overlay** when switching to the published v1.3.0 release; do not stack
the development PR on its own released code. Existing saved workflows should
continue to load with the `manual` default.

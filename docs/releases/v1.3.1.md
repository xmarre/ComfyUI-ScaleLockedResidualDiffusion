# ComfyUI Scale-Locked Residual Diffusion v1.3.1

## Reason for this update

In v1.3.0, Krea 2's opt-in `trajectory_auto` and
`trajectory_auto_native` policies can reduce each completed-latent
high-resolution restart to only two actual solver evaluations. Increasing the
node's `steps` value also increases the planner's steps, but does **not**
necessarily increase this two-evaluation high-resolution suffix. The separate
`stage_planning=auto_two_passes` selector determines resolution-stage count,
not the step budget within a stage. This distinction previously lacked a
dedicated control.

## Changed

- Append `highres_min_step_fraction` to the Krea 2 node after all existing
  widgets. The default is **0.25**, adjustable from **0.00 to 1.00**.
- For each automatic **completed-latent** high-resolution restart, retain at
  least `max(2, ceil(steps × fraction))` native solver updates, capped by the
  actual native schedule available after `composition_lock_sigma` releases
  the trajectory. The original SNR-based policy can still select more.
- Examples before the release cap: 14 steps → at least 4 high-resolution
  updates; 16 → 4; 20 → 5. If fewer native updates exist after release, keep
  all available updates and explicitly log the requested/available/selected
  counts.
- When the minimum exceeds two, use the existing native sigma suffix and
  discard any retimed two-step sigma grid. Do not fabricate sigma knots,
  alter the stochastic solver, bypass composition lock, or re-noise from a
  full-noise initial state.
- **Set `highres_min_step_fraction=0.00` to reproduce v1.3.0's exact
  unbounded adaptive shortening**, including its two-step retiming.
- The setting does not affect regular `trajectory`, `planner_final_img2img`,
  `spectral_progressive`, or other regeneration modes. Explicit stage
  megapixel layouts and the automatic spatial-stage policy remain independent.

## Compatibility

Existing saved workflow connections and widget positions are preserved:
the new control is appended at the end, and missing values use the default.
**The 0.25 default intentionally changes high-resolution step counts for
upgraded v1.3.0 workflows using automatic completed-latent regeneration.**
Users who need to reproduce previous images must explicitly set 0.00.

The setting is a minimum budget, not a direct request to execute the same
number of model evaluations as the planner. At most the post-release
native suffix is available: restarting from earlier than that release would
alter the composition-preservation contract.

## Validation and remaining limitations

Numerical tests cover 14/16/20-step budgets, release clipping,
two-step-retime replacement, invalid values and unchanged old behavior with
fraction=0. Native ComfyUI integration checks model-call counts for both
Euler and ER-SDE against the former two-step behavior and verifies the planner
output remains unchanged.

More high-resolution denoising can improve detail, but can also strengthen
incorrect anatomy, blemishes or identity drift, particularly with additional
MODEL modifications such as Diff-Aid, Spectrum and sparse attention. The
default 0.25 is a conservative initial budget, not an empirically established
quality optimum. GPU image quality must be evaluated on representative prompts.

## Upgrade

Install v1.3.1 through the ComfyUI Patcher/release workflow, and avoid stacking
a development overlay for the same changes over the released version.
